# 无后缀文本预览默认关闭：1226

已安装 `/Applications/OrbisPeek.app` 0.1.1（1226）。App 单页新增“无后缀文本预览”开关，默认关闭；用户开启后才尝试既有保守文本预览。实际 Finder 对同一文件的“关 → 开 → 关”和 App 退出 / 重开持久化均通过。测试结束时保持关闭。

## 实现

- App Group 内的 `preview-preferences-v1.json` 保存版本和开关值。每次真实读取，最多 4 KiB，原子替换写入，不依赖进程内偏好缓存。
- 设置缺失、损坏、版本不支持、过大或共享配置不可用时按关闭处理。不把 1225 的默认接管迁移成开启，也不在首次启动时自动写入开启。
- UI 仅在保存成功后更新开关；失败沿用现有提示，保留原值。现有介绍和目录管理保留，紧凑行中增加开关与“更改后请重新打开预览”的说明。目录列表最多两行可见，仍可滚动访问其他项目。
- 仅实际类型直接为 `public.data` 的请求读取该设置。关闭时在正文加载前向 Quick Look 返回系统行为，既有 Markdown / JSON 等格式不依赖开关。
- 严格加载路径也重新检查设置，旧恢复票据不能绕过关闭。已打开的内容不实时撤销；更改后关闭并重新打开预览使用新设置。隐藏恢复时发现功能关闭可能提示重新打开。
- 类型声明保持 194 项，没有改签名 plist 或重新登记提供器来切换设置；HTML 继续使用系统预览。任意动态后缀的限制、保守 Unicode 判定与读取失败回退范围沿用 [1225 验收](unclassified-text-validation-2026-11-15.md)。

## 实际验收

安装前设置文件不存在；没有清空真实设置或授权来模拟默认状态。

| 操作 | 结果 |
|---|---|
| 首次启动 1226 | 开关显示 off，原个人目录授权仍可见 |
| 关闭时 Space 预览合成无后缀文本 | 系统图标 / 文件信息，无本扩展正文 |
| 在 App 开启，退出 App，再预览同一 URL | 出现本扩展正文、格式 / 编码 / 大小 / 行数与换行图标；无需宿主常驻 |
| 开启时预览二进制 | 保守拒绝，恢复系统图标 / 信息 |
| 重新启动 App | 开关仍为 on，证明保存成功 |
| 关闭，再退出 App，重新 Space 同一 URL | 回到系统图标 / 信息；样本内容和修改时间未改变，未做缓存重置 |
| 再次启动 App | 开关保持 off，作为最终状态 |
| 关闭开关时 Markdown | 渲染与原文切换正常，无查找入口 |
| 关闭开关时 HTML | 继续显示系统 `file://` 正文 |

首次关闭与开启后的预览使用同一个扩展 PID 66325；宿主退出后该进程仍读到了新设置。再次关闭时系统自然创建了 PID 66809，因此不把三阶段说成同一进程。测试期间没有人为重启扩展或 Finder。
