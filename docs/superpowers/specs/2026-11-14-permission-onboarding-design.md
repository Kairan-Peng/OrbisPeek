# 单页宿主与按需图片授权

依据用户明确要求：宿主仅展示名称、logo、slogan 和目录授权管理；首次使用默认建议个人目录，保留其他项目或笔记目录入口，图片不可读时有清晰入口，预览保持简洁。不增加后台组件。

## 宿主

约 600×600 的原生单页，顶部为应用图标、OrbisPeek、中英 slogan。无目录时，目录区就是首次使用引导，主入口“允许读取个人目录…”、次入口“选择其他目录…”，提供只读及稍后设置说明，不自动弹选择器。已有目录时，显示紧凑可滚动列表、添加图标和每行移除图标，完整路径可查看；添加图标的菜单提供同样两项。

个人目录来自当前 UID 的账号主目录，仅用于定位原生选择器；失败回退普通选择器，不把容器或猜测路径当作个人目录。选择器附着主页，同时只展示一个，取消不修改授权。只有用户确认后才使用实际选中 URL 保存只读书签；添加 / 移除后提示重开预览。

侧栏、格式介绍、类型数量、自检、样本、诊断和嵌入文档预览不再进入宿主页面。标准文件菜单的打开动作与 HTML 打开方式继续创建独立阅读窗口。开发用核心诊断与 probe 保留。

## 预览中的授权入口

正常预览不增加工具栏控件。只有受控本地图片实际加载失败时，在可信父页面显示一条低调提示和一个“允许图片访问…”按钮；原图位置保留小占位和 alt。提示同时说明图片可能缺失或未获授权，避免把所有失败归因权限。远程、SVG 或越界路径被策略拒绝时，不引导用户扩大授权。

Markdown 与 HTML 使用同一父页面入口。进入原文、换文件、旧图片晚回调或旧按钮均不能留下或触发入口；提示和按钮不进入正文纯文本复制。查找继续移除。

## 边界与管理

显式点击只发送当前请求 UUID 和视图代次。原生端检查可信主 shell、当前 webView、活动请求、成功渲染及当前代次，再异步复核 live DOM 是否仍有当前失败入口；通过后只打开固定 `orbispeek://image-access`。文档自带自定义协议链接仍不可触发。宿主对固定路由分别处理冷 / 热启动，进入同一管理页，不携带目录路径、不自动授予权限。

公开系统接口返回失败时，仅对当前请求 / 视图显示手动打开应用、在目录权限中选择或添加文档目录并重开预览的步骤，兼容首次空态和已有列表，移除失效按钮；旧 completion 不影响新文档。本机 Finder 以该失败反馈验收，独立阅读器的直接入口另行验证。

逐目录移除原子更新共享授权，只清理对应本进程缓存，保留其他目录。其他进程仍按既有共享 UUID 校验失效；已打开预览的 scope 仍在关闭后释放。现有授权原样保留。

## 验收

覆盖严格路由、逐项移除隔离存储、请求 / 代次、旧按钮 / 回调、原文、HTML 可信父页面、提示复制排除。以纯值 SwiftUI 快照检查首次空态和多目录布局，避免撤销用户授权模拟首次使用。构建签名安装后，在原有授权之外的受控合成目录验证 Finder 提示、冷 / 热启动进入宿主、添加 / 移除和图片恢复，并回归真实 README 及独立 HTML 阅读。
