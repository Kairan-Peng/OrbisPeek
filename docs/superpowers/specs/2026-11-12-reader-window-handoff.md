## 行为

- Finder 的 Space 行为和已有可用格式保持；扩展的放大镜改为“在窗口中查找”，点击后按需打开现有 OrbisPeek 应用中的精简阅读窗口，自动展开并聚焦查找。Finder 内不再展示无法输入的网页查找栏，也不再强制远程视图 first responder。
- 阅读窗口复用受控渲染组件：Markdown / HTML 默认渲染、原文往返、JSON/JSONL/源码已有模式、换行、当前正文选区复制和 ⌘F/IME 均保留。仍无“复制”按钮，保持单行文件信息与三个图标。窗口可关闭和缩放，不新增常驻 helper、全局键盘监听或辅助功能权限。
- HTML / HTM / XHTML 通过 Finder“打开方式 → OrbisPeek”进入同一阅读窗口。宿主只增加精确 HTML/XHTML Viewer + Alternate 声明；不设为默认打开应用，不重新定义 HTML 类型，不扩展 Quick Look 的宽泛类型声明。安装前后实际默认应用必须一致。
- 当前安装 / 设置窗口的功能保留。独立阅读窗口拥有独立的预览、加载任务和文件读取 scope；关闭时取消并释放。不得由旧加载或后台回调激活其他应用、抢占新窗口焦点。

## 文件交接

1205 实际验证发现当前 Quick Look 沙盒拒绝在 App Group 创建请求目录，因此原一次性共享请求文件方案已被以下标准文件打开批次取代；产品入口保持不变。此前请求文件的自动测试不再作为最终跨进程交接依据。

使用公开 NSWorkspace URL 数组打开 API，在同一个批次交付当前文档 URL 与签名扩展资源中的静态 HTML 查找标记，明确指定当前扩展所属的宿主 app。禁用运行副本替换，启用本次显式打开的激活、禁止加入最近项目；不使用 launch arguments、自定义 URL scheme 或自定义 Apple event。当前文档通过系统标准文件打开路径传递读取授权，标记仅承载查找意图。

宿主使用公开 AppKit 文件打开 delegate，保留整批 URL，冷启动时可排队等待唯一 model 接入，设置窗口关闭后仍能接收。只有同批中与自身嵌入扩展资源精确规范 URL 一致的标记可赋予 `find`；先剔除标记再逐文档打开。仅标记的批次忽略，意图不跨事件保留，任意同名 / 伪造标记不被当作意图或额外读取授权。普通 HTML 打开方式无标记，按普通文件进入阅读窗口。文件读取 scope 在窗口生命周期内保持，关闭时释放。

只有成功且仍属当前读者、文件已渲染且窗口为 key 时，才一次性展开查找；切换窗口 / 文件或关闭后的旧回调不触发激活。交接失败在原 Finder 预览中给出可操作的简短错误，不回退为不可输入的原位查找栏。
