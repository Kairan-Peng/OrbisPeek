# 单页宿主与图片目录引导

已完成并安装 0.1.1（1214）。单页介绍、首次空态引导、目录添加 / 逐项移除、图片恢复及原有授权保留均通过。独立阅读器的授权按钮可直接进入管理页；本机 Finder 的公开打开接口返回失败，点击后会显示明确的手动设置步骤，该限制未伪记成直接启动通过。

## 当前实现

- 主窗口为约 600×600 的单页，仅保留应用图标、名称、中英 slogan 和目录权限区。没有旧侧栏、格式介绍、自检、样本或诊断按钮。标准文件菜单与 HTML 独立阅读窗口保留。
- 无目录即首次使用引导，提供一次性选择常用项目 / 笔记目录的按钮，可稍后设置；不会自动打开选择器。已有目录显示添加及逐项移除图标，移除一条不影响其他授权。
- 正常预览无新增工具栏按钮；实际本地图片加载失败才出现一条低调提示及一个授权入口。远程 / SVG / 越界策略拒绝不引导扩大授权，原文和旧请求清理入口，提示不进入复制正文。
- 入口只携带当前请求 UUID 与视图代次，经过可信主文档、当前 webView、成功渲染、视图代次及 live DOM 再检查，只打开固定 `orbispeek://image-access`。宿主冷 / 热启动进入同一目录页，不自动授权。

## 已完成检查

最终 115 项 JavaScript、76 项 Swift（49 Core + 27 UI）通过。1214 的实际 WebKit 提示 21 项通过；本轮前阶段的图片 23 项、原生 Copy 19 项回归通过，原剪贴板完整恢复。纯文本投影仍排除手动提示，不将自动检查写成 Finder 全量实体复制重验。独立只读审查通过；第一次使用空态与两目录列表另以无存储依赖的生产 SwiftUI 600×600 快照检查，不清空真实授权来模拟首次使用。

1210 原始候选的 Finder 本地图片失败提示正常，但直接 `NSWorkspace.open` 未启动宿主。1211 改为明确的 containing app 异步打开后，回调返回 `NSCocoaErrorDomain 256`，系统同时记录缺少跨会话启动的私有权限；没有添加该权限或后台 helper。期间电脑控制曾出现只能读取快照、输入返回 `noWindowsAvailable`，经用户切回 Finder 后恢复；不将该会话现象概括为所有系统必然禁止。

1212 在真实扩展内优先使用系统提供的 `extensionContext.open`；普通独立阅读器继续显式打开自身 app。该公开方法由每个 extension point 决定是否支持；本机真实 Finder completion 为 `false`。[Apple 的接口说明](https://developer.apple.com/documentation/foundation/nsextensioncontext/open(_:completionhandler:))

1213 补充当前请求 / 视图代次限定的失败反馈，并移除失效按钮。1214 仅将文案修正为兼容首次空态和已有列表的“请在‘应用程序’中打开 OrbisPeek，在‘目录权限’中选择或添加文档所在目录，再重新打开预览。”旧 completion、旧按钮、换文件、原文模式和同代晚到图片错误均有回归，提示不进入正文复制。

## 真实界面验收

- 真实宿主单页已打开，原有目录列表保留，最终截图见 `.build/validation/permission-onboarding-1214/host-final.png`。
- 实测开始时，用户当前原有授权为账号主目录（已由用户自行调整，不再是先前仅项目的记录）。本轮保持原样，因此未授权对照使用 `/private/tmp/orbispeek-permission-1210-pqgfeuw0` 中的合成文档与已知 PNG；未读取其他用户文档。
- Finder 未授权对照确实显示单条提示和占位。点击后公开接口返回 `false`，实际更新为手动步骤且按钮消失；不是静默无效，也没有宣称直接唤起成功。
- 按步骤打开宿主，添加合成目录后，原有账号主目录与测试目录同时存在。退出宿主后重开 Finder，图片正常显示，提示 / 授权按钮消失；渲染 → 原文 → 渲染往返保持正确图片及源码标签。
- 只点击测试目录对应的移除图标，原有目录保持不变。随后由 Finder 正常“打开方式 → OrbisPeek”冷启动 HTML 独立阅读器，图片再次受限，证明撤销作用于新预览；受限入口仍位于可信父页面。
- HTML 阅读器点击入口后，直接显示同一管理页；原生回调记录 `hostOpen completed`、同一应用 PID 和 `exactTarget=true`。该项与 Finder 手动步骤的结果分开记录。
- 结束时测试目录授权已移除，原有授权保留；自建 Finder 测试标签与 HTML 窗口已关闭，原项目和“资料”标签保留，真实 README 图标及无额外提示的预览已恢复。最终留下新版单页供用户查看。
- 添加、移除和 HTML 直接入口的完整交互证据保留在 1213 目录。1214 除两份 renderer 源 / 生成文件中的手动文案外，29 份运行时冻结文件中的其余 27 份完全一致；重新安装后，Finder 受限提示点击、最新手动文案、失效按钮消失、原 README 图片及宿主原有目录均再次实测通过。
- 1210–1214 的源码冻结、候选 / 安装验证及故障证据分别保留在 `.build/validation/permission-onboarding-<build>/`。最终安装核对 59 份文件、六份网页资源、195 项精确类型与唯一插件登记。1214 初次登记尚无匹配，针对安装路径重试一次 `pluginkit -a` 后完成登记并复验通过；首次失败报告保留。没有全局缓存重置或终止 Finder。原 1209 及后续开发候选均有 ZIP 和可恢复 bundle 备份。
