已安装 `/Applications/OrbisPeek.app` 0.1.1（1225），交付验证可行的直接 `public.data` 文本尝试，主要覆盖无后缀文件。**任意陌生 `dyn.*` 后缀尚不能通用接管**；生产没有枚举实验动态类型。HTML 明确保留系统预览，查找和宿主文档打开入口继续移除。

## 机制验证

所有文件均为隔离目录下的合成数据，不用用户工作文档测试。原型使用独立签名标识、只读沙盒、限定的合成目录；没有替换正式 1220 或新增目录授权。先保存系统基线，再在新路径中测试，避免把旧预览缓存当作新分发。

| 声明 / 输入 | 实际 Finder 结果 |
|---|---|
| 未登记原型，陌生后缀 / 无后缀文本与二进制 | 系统图标和大小 / 修改时间，没有正文 |
| 仅 `public.data`，实际类型直接为 `public.data` 的无后缀 UTF-8 | 原型 received / accepted 日志及完成后的原生正文 marker 通过 |
| 同一声明，无后缀二进制 / 强制 Cocoa259 错误 | received / rejected 后恢复与基线一致的系统图标 / 元数据，没有自定义错误页 |

陌生后缀的实际类型为 `dyn.ah62d4rv4ge8086xcrf31n5xpr311s5v1qy6xe2u`，它虽然 conforms `public.data` / `public.item`，本机 Quick Look 没有按这些祖先声明分发。无后缀和合成 dotfile 的元数据是直接 `public.data`。不能把 UTI conformance 或声明存在等同于 Finder 实际调用。

早期 1221 / 1222 快照曾捕获加载中的白屏，不计完成或失败结论；1222 的后续完整快照实际显示了 marker 与正文。没有证明几何布局是早期白屏的根因。大文件在最终安装中也以完成后的截图验收，不用不完整的 AX 树推断正文缺失。

[Apple 的 preparePreview 方法](https://developer.apple.com/documentation/quicklookui/qlpreviewingcontroller/preparepreviewoffile(at:completionhandler:))没有承诺错误后选择下一提供器。本轮验证的是本机恢复原来的系统图标 / 信息，**没有证明链式调用另一内容提供器，也没有承诺无后缀 PDF 会被重新识别成 PDF**。

## 正式实现

- 扩展共 194 项声明：193 个既有语义类型，加唯一额外的 `public.data`；没有 `public.item`、`public.content` 或 `dyn.*`。HTML/XHTML 从预览声明移除，格式识别和共享渲染实现保留。
- 先按实际文件类型分流。既有精确类型保持原模式；仅实际类型直接为 `public.data` 才尝试保守纯文本。其他语义类型和动态类型留给系统，不凭文件名越过媒体 / 二进制冲突边界。
- `TextDecodingPolicy.verifiedUnicode` 只接受严格 UTF-8 或明确 UTF-8/16/32 BOM；不做旧编码及无 BOM UTF-16 推测。一个确定为 opaque 的样本会被旧探测器猜成 ISO-8859-1，因此不能只用“可无损解码”作为未知文本证据。已支持格式默认 `.automatic`，旧编码兼容保持。
- 加载通过统一 `showFile` 策略，建立请求失效保护后只读一次；不保留独立预读旁路。首次读取 / 编码 / 二进制拒绝不显示本应用错误页，直接向 Quick Look 抛回错误，并释放文件与目录 scope。
- 恢复票据保存同一严格策略，重新读取，不重用旧 payload。关闭和新请求会使迟到结果失效。恢复期间文件变坏时，由于没有新的 Quick Look 完成回调，显示“无法恢复预览。请关闭后重新按空格预览。”；关闭重开后才重新进行系统回退。异步 WebKit 导航 / 渲染失败仍使用既有错误界面。
